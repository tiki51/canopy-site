About five minutes from install to your first agent reply. By the end you'll have Canopy running at `http://localhost:4000`, Claude Code checked in Settings, a project registered, and a channel where an agent has answered you without changing a single file.

| At a glance | |
|---|---|
| Time | ~5 min total (Homebrew) or ~10 min (from source) |
| You need | Claude Code installed and logged in; git |
| Simple first prompt | Read-only |

<Steps>

1. ## Check Claude Code and log in

   Claude Code must be installed and logged in on this machine. Canopy uses that local login; it does not ask for an Anthropic API key.

   Verify Claude Code from any terminal:

   ```bash
   claude --version
   ```

   If Claude Code has not been logged in here yet, run `claude` once and complete its login flow.

   :::note[Checkpoint]
   `claude --version` reports an installed Claude Code binary.
   :::

2. ## Install Canopy

   <Tabs>
     <TabItem label="Homebrew (Apple Silicon)" icon="apple">
       ```bash
       brew install tiki51/canopy/canopy
       canopy
       ```

       Homebrew installs Canopy and all dependencies. `canopy` starts it at [127.0.0.1:4000](http://127.0.0.1:4000) and seeds thirteen starter agents.

       :::note[Checkpoint]
       Canopy opens at [127.0.0.1:4000](http://127.0.0.1:4000) with the agent roster visible.
       :::
     </TabItem>
     <TabItem label="From source (any OS)" icon="github">
       You need Elixir 1.20 with Erlang/OTP 28 and git.

       ```bash
       git clone https://github.com/tiki51/canopy
       cd canopy
       mix setup    # dependencies, database, and thirteen starter agents
       ```

       `mix setup` compiles dependencies, creates the development database, and seeds thirteen starter agents, from `@backend` to `@reviewer`. The first run takes a few minutes and only happens once.

       Then start the server:

       ```bash
       mix phx.server
       ```

       Open [localhost:4000](http://localhost:4000).

       :::note[Checkpoint]
       Canopy opens at [localhost:4000](http://localhost:4000) with the agent roster visible.
       :::
     </TabItem>
   </Tabs>

3. ## Check Claude Code in Settings

   Open **Settings** from the gear in the left rail. Under **Claude Code**, verify the **Binary** path (usually `claude` if it is on your PATH). Choose **Check Claude Code** to confirm it is installed and you are logged in.

   :::note[Checkpoint]
   Settings confirms Claude Code is installed and logged in.
   :::

4. ## Choose Claude Code for an agent

   Open **Agents** and choose the agent that will own your first task (e.g. `@backend`). Select **Claude Code** as its engine and fill in three settings:

   - **Model:** Choose `opus`, `sonnet`, `haiku`, or `fable` (Claude Code resolves these to the latest model in each family), or pick any model your Claude Code login has access to.
   - **Effort:** Choose `medium` for balanced speed and cost.
   - **Permissions:** Leave **Tools that run without asking** blank to use the default allow-list.

   Then save.

   :::details[Default tools Claude Code agents can use without permission]
   **Read, Glob, Grep, Edit, Write, MultiEdit, NotebookEdit, Bash(git *), and all Canopy tools.** Canopy tools are always allowed. Everything else asks first.
   :::

   With **ask first** enabled, any tool outside the allow-list appears as a permission card in the channel; choose to allow it once, always, or reject it. Agent questions also appear as cards there. Each agent chooses its own engine independently, so Claude Code and OpenCode agents can collaborate in the same channel.

   In **Settings**, you can also set an optional per-turn spend cap in USD for Claude Code.

   :::note[Checkpoint]
   The agent shows Claude Code as its engine, with a model and effort level set.
   :::

5. ## Add a repository and channel

   Open **Repositories** and add a local project folder. It should be inside your home directory; a path outside it requires the checkbox on the form. It does not need to be a git repository; if the folder is not one, Canopy runs `git init` and otherwise never modifies it. Registering also creates a small `.canopy/` workspace inside the project with shared notes and one notes file per agent, listed in `.git/info/exclude` so it never shows up in your diffs.

   With a project in place, create a channel. Its name becomes the `#slug` in the sidebar; the topic is one line on what the channel is for. Choose the Claude Code agent you configured as owner and leave the other members unchecked for this first task. The owner is who a plain, unaddressed message wakes.

   :::note[Checkpoint]
   The repository appears, the channel opens, and its Claude Code owner is visible.
   :::

6. ## Send a simple first task

   Post: *"Inspect this repository and tell me which test command I should run first. Do not edit files."* An unmentioned message wakes the channel owner; mentioning an agent wakes only that agent.

   Watch the channel header: the owner's dot turns green and a live card opens under the message. The reply arrives as an ordinary message. Turn on **Activity** in the header to see the finished line with its tools, reported cost, and duration.

   If Claude Code needs approval or an answer while it works, Canopy shows the request in the channel. Review it there before responding.

   :::note[Checkpoint]
   The owner shows working, then posts a reply and records the outcome in the timeline.
   :::

</Steps>
