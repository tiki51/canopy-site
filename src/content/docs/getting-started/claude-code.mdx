About five minutes from install to your first agent reply. By the end you'll have Canopy running on your machine, Claude Code as the default engine, a project registered, and a channel where an agent has answered you without changing a single file.

| At a glance | |
|---|---|
| Time | ~5 min total (Homebrew) or ~10 min (from source) |
| You need | Claude Code installed and logged in; git |
| Simple first prompt | Read-only |

<Steps>

1. ## Check Claude Code and log in

   Claude Code must be installed and logged in on this machine. Canopy uses that local login; it does not ask for an Anthropic API key.

   Verify Claude Code from any terminal:

   ```bash
   claude --version
   ```

   If Claude Code has not been logged in here yet, run `claude` once and complete its login flow.

   :::note[Checkpoint]
   `claude --version` reports an installed Claude Code binary.
   :::

2. ## Install Canopy

   <Tabs>
     <TabItem label="Homebrew (Apple Silicon)" icon="apple">
       ```bash
       brew install tiki51/canopy/canopy
       brew services start tiki51/canopy/canopy   # runs in the background, starts at login
       canopy seed                                # the thirteen starter agents
       ```

       Homebrew installs a prebuilt release, so nothing else needs installing. Open [127.0.0.1:4000](http://127.0.0.1:4000). `canopy start` runs Canopy in the foreground instead (`Ctrl-C` quits), and `canopy seed` is safe to run again: it only adds back a missing starter agent.

       Your database, shared files, and generated secret live under `~/Library/Application Support/Canopy`; the service logs to `$(brew --prefix)/var/log/canopy.log`.

       :::note[Checkpoint]
       Canopy opens at [127.0.0.1:4000](http://127.0.0.1:4000) with the setup window over it.
       :::
     </TabItem>
     <TabItem label="From source (any OS)" icon="github">
       You need Elixir 1.20 with Erlang/OTP 28 and git.

       ```bash
       git clone https://github.com/tiki51/canopy
       cd canopy
       mix setup    # dependencies, database, and thirteen starter agents
       ```

       `mix setup` compiles dependencies, creates the development database, and seeds thirteen starter agents, from `@backend` to `@reviewer`. The first run takes a few minutes and only happens once. `mix run priv/repo/seeds.exs` adds back a missing starter agent later without touching the ones you changed.

       Then start the server:

       ```bash
       mix phx.server
       ```

       Open [localhost:4000](http://localhost:4000).

       :::note[Checkpoint]
       Canopy opens at [localhost:4000](http://localhost:4000) with the setup window over it.
       :::
     </TabItem>
   </Tabs>

3. ## Walk through first-run setup

   The first time you open Canopy, setup opens as a window over the app. It has six short steps (**You**, **Look**, **Engines**, **Pace**, **Notifications**, **Project**), and every choice saves as you make it.

   <Shot name="setup-modal" scale={1} alt="Canopy first-run setup window over the dimmed app, on the Engines step" caption="Setup checks all three engines as it opens and picks the default engine for you." />

   - **You**: the name agents call you, prefilled from your git `user.name`.
   - **Look**: light, dark, or system, and one of four palettes.
   - **Engines**: Canopy checks Claude Code, Codex, and OpenCode, and shows Claude Code's version and the account it is logged in as. When Claude Code is ready it becomes the **default engine**, which the thirteen starter agents run on. Pick the **default model** (`fable`, `opus`, `sonnet`, or `haiku`, the latest of each family) and default effort.
   - **Pace**: how much agents do on their own. **Balanced** is the default; see [Settings](/canopy-site/docs/settings/#personalize-and-pace-conversations).
   - **Notifications** (optional): desktop notifications when an agent needs you.
   - **Your first project** (optional): a folder on this machine and a name. It does not need to be a git repository; if it is not one, Canopy runs `git init` and otherwise leaves it alone.

   If setup says **Claude Code not found**, give the path to `claude` in the field that appears and press *Check*. If it says **not logged in**, run `claude` once in a terminal, then *Check again*.

   :::note[Checkpoint]
   The Engines step shows Claude Code as ready and selected as the default engine.
   :::

4. ## Create a channel

   **Finish setup** shows a summary. Choose *Start a channel*: the New channel form opens with your project already picked.

   Its name becomes the `#slug` in the sidebar; the topic is one line on what the channel is for. Every active agent is ticked as a member by default: use **Clear all**, tick one agent (e.g. `@backend`), and make it the **Initial owner**. The owner is who a plain, unaddressed message wakes.

   :::note[Checkpoint]
   The channel opens, empty, with its owner in the header's agents button.
   :::

5. ## Send a simple first task

   Post: *"Inspect this repository and tell me which test command I should run first. Do not edit files."* An unmentioned message wakes the channel owner; mentioning an agent wakes only that agent.

   The owner's dot in the header turns green and a live card opens under your message, naming what it is running now. The reply arrives as an ordinary message, and the turn ends in a card headed `@agent finished · N tools · $cost · duration`: click it for every call the agent made.

   If Claude Code needs approval or an answer while it works, a permission or question card appears in the channel. Answer it there.

   :::note[Checkpoint]
   The owner shows working, then posts a reply and records the outcome in the timeline.
   :::

</Steps>

## Tune an agent (optional)

Agents follow the defaults from setup until you give them their own. Open **Agents**, choose an agent, and choose **Edit**:

- **Engine:** *Default (Claude Code)* follows Settings; pick Claude Code, Codex, or OpenCode to pin it.
- **Model** and **Effort:** leave them on *Default (…)* or pick one for this agent.
- **Permissions:** ask before any tool not on the list, also approve file edits without asking, or read-only planning. **Tools that run without asking** takes one pattern per line, such as `Bash(git *)`.

:::details[Default tools Claude Code agents can use without permission]
**Read, Glob, Grep, Edit, Write, MultiEdit, NotebookEdit, Bash(git *), and all Canopy tools.** Canopy tools are always allowed. Everything else asks first.

Filling in **Tools that run without asking** replaces this list rather than adding to it. Leave Edit and Write off an agent's list and its edits ask first, with the diff on the card, unless its permission mode approves file edits.
:::

Any tool outside the allowance appears as a permission card in the channel: allow it once, for the session, globally (every channel, until you remove it on the agent's page), or reject it. In **Settings → Claude Code** you can also set an optional spend cap per turn in USD.
