This guide connects OpenCode to Canopy. The first task takes about five minutes once both services are running.

By the end, Canopy will be running on your machine with OpenCode as the default engine, one local project will be registered, and an OpenCode agent will have answered a read-only task. You can mix OpenCode and Claude Code agents in the same channel.

<Steps>

1. ## Check OpenCode and a configured provider

   OpenCode 1.18+ must be installed with a configured provider that supplies the model your agents use.

   ```bash
   opencode providers
   ```

   If no provider is listed, configure one now (your API key, credentials, or model preference) before proceeding.

2. ## Install Canopy

   <Tabs>
     <TabItem label="Homebrew (Apple Silicon)" icon="apple">
       ```bash
       brew install tiki51/canopy/canopy
       brew services start tiki51/canopy/canopy   # runs in the background, starts at login
       canopy seed                                # the thirteen starter agents
       ```

       Homebrew installs a prebuilt release, so nothing else needs installing. Canopy answers at [127.0.0.1:4000](http://127.0.0.1:4000); `canopy start` runs it in the foreground instead.

       :::note[Checkpoint]
       Canopy opens at [127.0.0.1:4000](http://127.0.0.1:4000) with the setup window over it.
       :::
     </TabItem>
     <TabItem label="From source (any OS)" icon="github">
       You need Elixir 1.20 with Erlang/OTP 28 and git.

       ```bash
       git clone https://github.com/tiki51/canopy
       cd canopy
       mix setup    # dependencies, database, and thirteen starter agents
       ```

       `mix setup` compiles dependencies, creates the development database, and seeds thirteen starter agents. The first run takes a few minutes and only happens once.

       :::note[Checkpoint]
       `mix setup` finishes without errors.
       :::
     </TabItem>
   </Tabs>

3. ## Start both services

   Keep OpenCode running in its own terminal.

   ```bash
   # Terminal 1
   opencode serve --port 4096

   # Terminal 2 (from source; Homebrew's service is already running)
   mix phx.server
   ```

   `opencode serve` runs models and tool calls. Canopy serves the UI at [localhost:4000](http://localhost:4000). Restarting either process preserves your work; Canopy reconnects automatically.

4. ## Walk through first-run setup

   The first time you open Canopy, a setup window opens over the app with six short steps: **You**, **Look**, **Engines**, **Pace**, **Notifications**, and **Project**. Every choice saves as you make it.

   On **Engines**, Canopy checks OpenCode and shows its version and URL. When only OpenCode answers it becomes the **default engine**, which the thirteen starter agents run on; when Claude Code is ready too, Claude Code is preselected, so click the OpenCode card to switch. Then pick the **default model**: the list comes from OpenCode's own providers.

   If setup says **OpenCode not running**, start `opencode serve --port 4096` and press *Check again*. If your server runs somewhere else, set its address later in **Settings → OpenCode server**.

   On **Project**, add a local folder and a name. It does not need to be a git repository; if it is not one, Canopy runs `git init` and otherwise leaves it alone.

   :::note[Checkpoint]
   The Engines step shows OpenCode as ready and selected as the default engine.
   :::

5. ## Install the identity plugin

   Open **Settings** from the gear in the rail and scroll to **MCP**. Copy the identity plugin to `~/.config/opencode/plugins/canopy.js` and restart `opencode serve`.

   The plugin stamps each OpenCode session id into Canopy tool calls so Canopy knows which agent is speaking. Canopy also installs a copy in every registered repository under `.opencode/plugins/`, excluded from git.

   :::note[Checkpoint]
   **Check connection** under **OpenCode server** shows the version in green.
   :::

6. ## Create a channel and send a first task

   Choose **+** next to *Channels* (or *Start a channel* at the end of setup). Give it a one-line topic, use **Clear all** to untick the default members, tick one agent, and make it the owner. A plain, unaddressed message wakes that owner.

   Post: *"Inspect this repository and tell me which test command I should run first. Do not edit files."*

   The owner's dot in the header turns green and a live card shows what it is doing, with a running cost. The reply arrives as an ordinary message, and the finished card records the turn's tools, cost, and duration.

   :::note[Checkpoint]
   The owner shows working, then posts a reply and records the outcome in the timeline.
   :::

</Steps>
