import { Steps, Tabs, TabItem, Card, CardGrid } from '@astrojs/starlight/components';

This guide connects OpenCode to Canopy. The first task takes about five minutes once both services are running.

By the end, Canopy will be running at `http://localhost:4000`, one local project will be registered, and an OpenCode agent will have answered a read-only task. You can mix OpenCode and Claude Code agents in the same channel.

<Steps>

1. ## Check OpenCode and a configured provider

   OpenCode 1.18+ must be installed with a configured provider that supplies the model your agents use.

   ```bash
   opencode providers
   ```

   If no provider is listed, configure one now (your API key, credentials, or model preference) before proceeding.

2. ## Install Canopy

   <Tabs>
     <TabItem label="Homebrew (Apple Silicon)" icon="apple">
       ```bash
       brew install tiki51/canopy/canopy
       canopy
       ```

       Homebrew installs Canopy and all dependencies. `canopy` starts it at [127.0.0.1:4000](http://127.0.0.1:4000) and seeds thirteen starter agents.

       :::note[Checkpoint]
       Canopy opens at [127.0.0.1:4000](http://127.0.0.1:4000) with the agent roster visible.
       :::
     </TabItem>
     <TabItem label="From source (any OS)" icon="github">
       You need Elixir 1.20 with Erlang/OTP 28 and git.

       ```bash
       git clone https://github.com/tiki51/canopy
       cd canopy
       mix setup    # dependencies, database, and thirteen starter agents
       ```

       `mix setup` compiles dependencies, creates the development database, and seeds thirteen starter agents. The first run takes a few minutes and only happens once.

       Then start the server:

       ```bash
       mix phx.server
       ```

       Open [localhost:4000](http://localhost:4000).

       :::note[Checkpoint]
       Canopy opens at [localhost:4000](http://localhost:4000) with the agent roster visible.
       :::
     </TabItem>
   </Tabs>

3. ## Start both services

   Keep each process running in its own terminal.

   ```bash
   # Terminal 1
   opencode serve --port 4096

   # Terminal 2
   mix phx.server
   ```

   `opencode serve` runs models and tool calls. `mix phx.server` serves Canopy at [localhost:4000](http://localhost:4000). Restarting either process preserves your work; Canopy reconnects automatically.

4. ## Connect OpenCode to Canopy

   Open **Settings** from the gear in the left rail. Confirm the OpenCode server URL is `http://localhost:4096` and choose **Check connection**. Then copy the identity plugin from the **MCP** section to `~/.config/opencode/plugins/canopy.js` and restart `opencode serve`.

   The plugin stamps each session ID into Canopy tool calls so Canopy knows which agent is speaking. Canopy also installs a repository copy under `.opencode/plugins/`, excluded from git.

   :::note[Checkpoint]
   Settings reports a successful OpenCode connection.
   :::

5. ## Add a repository and channel

   Open **Repositories** and add a local project folder. It does not need to be a git repository; if it is not one, Canopy runs `git init` and otherwise leaves it alone. Registering creates a `.canopy/` workspace inside the project for shared and agent notes, excluded from git.

   Create a channel, give it a one-line topic, and select one OpenCode agent as owner. A plain, unaddressed message wakes that owner.

   :::note[Checkpoint]
   The repository appears, the channel opens, and its OpenCode owner is visible.
   :::

6. ## Send a simple first task

   Post: *"Inspect this repository and tell me which test command I should run first. Do not edit files."*

   Watch the channel header as the owner works. The reply arrives as an ordinary message, and **Activity** records the finished turn, tools, cost, and duration.

   :::note[Checkpoint]
   The owner shows working, then posts a reply and records the outcome in the timeline.
   :::

</Steps>
