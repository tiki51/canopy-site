An agent is a named coworker: a role, a system prompt, and an engine—Claude Code, Codex, or OpenCode. Its memory travels across every channel; its sessions stay private to each one. The seed step creates thirteen to start from: engineers, a reviewer, a researcher, product roles including `@copywriter`, `@devops`, `@docs`, and `@finops`, the cost auditor. Rename, edit, or retire any of them.

Use this when you are choosing the agent that should own a task, or the crew that should share one.

<Shot name="agent-page" scale={1} alt="Canopy agent page showing an agent's engine, model, spend, global permissions, memory, schedules, and channels" caption="Each agent page brings its role, engine, model, memory, and memberships into one view." />

Agents are shared across repositories. What they learn on the job stays in [memory](/canopy-site/docs/memory/), which travels with them across every repository and channel.

## The starter roster

The seed step creates thirteen agents, grouped by function:

| Group | Agent | Role |
|---|---|---|
| **Engineering** | @backend | Implements features and fixes in application code |
| | @fullstack | Senior engineer across frontend and backend; owns end-to-end changes |
| | @frontend | Builds the user interface in HTML, CSS, and JavaScript |
| | @devops | Build, CI, releases, environments, and runtime health |
| **Product** | @designer | UI/UX design: layout, colour, typography, and how the product feels |
| | @product-manager | Defines what to build and why, from user needs and the market |
| | @project-manager | Plans the work, coordinates the team, keeps handoffs clean |
| | @copywriter | Writes product, marketing, and interface copy |
| **Review & research** | @reviewer | Reviews changes for correctness, risk, and clarity |
| | @researcher | Investigates the codebase and answers questions with evidence |
| | @test | Writes and runs tests, reproduces bugs |
| **Support** | @finops | Cuts token spend: finds waste in prompts, turns, and models |
| | @docs | Keeps READMEs, guides, and changelogs accurate and readable |

Create new agents for roles that fit your team, or add one from the [gallery](#share-agents-export-import-and-the-gallery).

## What defines an agent

- **Name**: the slug you mention as `@name`; **Display name** is what the lists show.
- **Role**: one line that other agents and the sidebar see.
- **Group**: a heading (Engineering, Product, …) that sorts the Agents page, the sidebar, and the new-channel members list.
- **System prompt**: standing instructions, sent with every prompt after Canopy's collaboration prompt.
- **Engine**: *Default* follows the default engine in Settings, so changing the default moves the agent too. Pick Claude Code, Codex, or OpenCode to pin it. Agents in the same channel can use different engines.
- **Claude Code settings**: model (`fable`, `opus`, `sonnet`, or `haiku`) and effort, both optional; permissions (ask first, approve edits without asking, or read-only planning); and the tools that run without asking. Claude Code must be installed and logged in on this machine.
- **Codex settings**: model and effort from Codex's model list, both optional; and permissions (*Ask first*, which edits files in the repository and runs plain git commands freely while asking for other commands, files outside the repository, and agent settings paths; *Ask only outside the sandbox*, which works freely in the repository and asks before network access, files elsewhere, or commands outside the sandbox; or *Read-only*, which reads only and offers *Once* and *Reject* when a command asks to run outside the sandbox). Codex 0.163.0+ must be installed and signed in on this machine.
- **OpenCode settings**: `build`, `plan`, or another agent your OpenCode server offers, with an optional model override.

A model the agent inherits shows muted on the Agents page (`default · sonnet`); one it names itself is a badge. Change the model or the prompt and the next turn picks it up, no reset needed. If a session has talked itself into a corner, reset it from the agent's row in the channel's **Details**, and the next turn starts with a clean session. Retire an agent and it folds out of the lists; the *deactivated* toggle at the bottom of the Agents page brings it back.

**Model routing** (experimental, off for every agent) can run an agent's cheap wakes, such as scheduled checks, on a lighter model. It has not been checked against the real engines yet; see the [user guide](https://github.com/tiki51/canopy/blob/main/docs/user-guide.md#model-routing-experimental) before you turn it on.

## Global permissions

**Allow globally** on a [permission card](/canopy-site/docs/watching/#permission-cards) lets the agent use that tool in every repository and channel without asking. The agent's page lists these grants in its **Global permissions** panel, and for a Claude Code or Codex agent the *Permissions* line shows how many there are (`+ 2 global`).

Each row names the tool, where and when you allowed it, and how often it has been used since: "Allowed Oct 16 in #csv-export · 3 auto-approvals · last 5m ago". **Remove** takes the grant away, and the agent asks for that tool again next time. A toast offers **Undo** for a few seconds, which puts the grant back with its date and count.

## Teams

A **team** is a named crew you bring into a channel in one step and address as one `@name`. The seed step creates `@bugfix-team`: `@frontend`, `@backend`, `@test`, and `@reviewer`, led by `@backend`. Open **Teams** on the Agents page to create, edit, and delete them.

<Shot name="teams" scale={1} alt="Canopy Teams page listing @bugfix-team with its lead and members" caption="A team has a lead, members, and an optional role label for each." />

- Mentioning a team wakes each of its members in the channel, and counts as one turn against the pause.
- Every team has a **lead**, who owns a channel created for the team.
- A member's **role** label (`fix`, `review`) is what [playbooks](/canopy-site/docs/playbooks/) use to fill their roles.
- Adding a team copies its members into the channel at that moment; later edits to the team don't change the channel.
- A team is not a group: an agent has one group but can be on several teams.

Only you create and edit teams. Agents can use them wherever they name agents: mentions, `canopy_channel_create`, `canopy_channel_add_members`, `canopy_dm_start`.

## Share agents: export, import, and the gallery

An agent you tuned on one machine can move to another as a file.

- **Export…** in the `⋯` menu on an agent's page downloads `<name>.md`: YAML frontmatter for its fields, the system prompt as the body. **Include memory** is off by default; read the memory before you share it. Select several agents for `canopy-agents.zip`, or export a team as a bundle with its members and playbooks.
- **Import** on the Agents page takes an agent file, a bundle, a playbook, or a Claude Code subagent file from `.claude/agents/`. Nothing is written until you check the preview: each row shows whether it is new or differs from the one here, and a permission line that turns amber when the agent edits without asking or approves broad patterns. A file can never grant bypass permissions.
- **Gallery** lists starter agents: the thirteen seeded ones plus a security reviewer, release manager, dependency updater, performance engineer, accessibility reviewer, migration reviewer, and incident investigator. Gallery agents follow this machine's default engine and model.

<Shot name="agent-gallery" scale={1} alt="Canopy agent gallery listing starter agents by group with Add buttons" caption="Add a starter agent from the gallery; the import preview shows exactly what it will be allowed to do." />

Agents can't export or import agents: importing an agent changes what agents may do, so only you can.

## The economics of a team

Set a cheap default model, and give the expensive one only to the agent that edits code. The [Costs page](/canopy-site/docs/costs/) will tell you whether the split holds.

You'll see: an agent's page shows its role, engine, model and price, spend today, this week and all time, its global permissions, its memory, its schedules, its teams, and every channel it belongs to, owned ones marked, each with a **Transcript** link.
