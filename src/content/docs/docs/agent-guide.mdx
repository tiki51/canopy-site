An agent is a named coworker: a role, a system prompt, and a per-agent engine choice: Claude Code or OpenCode. Its memory travels across every channel; its sessions stay private to each one. `mix setup` creates thirteen to start from — engineers, a reviewer, a researcher, product roles including `@copywriter`, `@devops`, `@docs`, and `@finops`, the cost auditor. Rename, edit, or retire any of them.

Use this when you are choosing the agent that should own a task.

Agents are shared across repositories. What they learn on the job stays in [memory](/canopy-site/docs/memory/), which travels with them across every repository and channel.

## The starter roster

`mix setup` creates thirteen agents, grouped by function:

| Group | Agent | Role |
|---|---|---|
| **Engineering** | @backend | Implements features and fixes in application code |
| | @fullstack | Senior engineer across frontend and backend; owns end-to-end changes |
| | @frontend | Builds the user interface in HTML, CSS, and JavaScript |
| | @devops | Build, CI, releases, environments, and runtime health |
| **Product** | @designer | UI/UX design: layout, colour, typography, and how the product feels |
| | @product-manager | Defines what to build and why, from user needs and the market |
| | @project-manager | Plans the work, coordinates the team, keeps handoffs clean |
| | @copywriter | Writes product, marketing, and interface copy |
| **Review & research** | @reviewer | Reviews changes for correctness, risk, and clarity |
| | @researcher | Investigates the codebase and answers questions with evidence |
| | @test | Writes and runs tests, reproduces bugs |
| **Support** | @finops | Cuts token spend: finds waste in prompts, turns, and models |
| | @docs | Keeps READMEs, guides, and changelogs accurate and readable |

Rename, edit, or retire any of them. Create new agents for roles that fit your team.

## What defines an agent

- **Name** — the slug you mention as `@name`; **Display name** is what the lists show.
- **Role** — one line that other agents and the sidebar see.
- **System prompt** — standing instructions, sent with every prompt.
- **Engine** — choose **Claude Code** or **OpenCode** for this agent. Agents in the same channel can use different engines.
- **Claude Code settings** — choose its model, effort, permission mode, and tools that can run without asking. Claude Code must be installed and logged in on this machine.
- **OpenCode settings** — choose `build`, `plan`, or another agent your OpenCode server offers, with an optional model override.

Change the model or the prompt and the next turn picks it up — no reset needed. If a session has talked itself into a corner, reset it from the channel header and the next turn starts with a clean session. Memory belongs to the individual agent, not the channel. Retire an agent and it folds out of the lists; the *deactivated* toggle at the bottom of the Agents page brings it back.

## The economics of a team

Pick a cheap model for agents that mostly acknowledge and report; keep the expensive one for the agent that edits code. The [Costs page](/canopy-site/docs/costs/) will tell you whether the split holds.

You'll see: an agent's page shows its role, model and price, its spend to date, its memory, its schedules, and every channel it belongs to — owned ones marked.
